# Cart thumbnail should always show the product's first (model) image

## Background:

- Raised by the client (ClaudiaG) on the Quick Launch Sprint Call – June 04 ([Fathom @38:46](https://fathom.video/calls/697645142?timestamp=2326.37)). While adding products to the cart, "some pulled in with ghosts, and then some pulled in the product images on the model." The client wants the cart to consistently show the **model image**.
- On the call it was confirmed that the **model image is always the first / main image** of the product ([Fathom @39:18](https://fathom.video/calls/697645142?timestamp=2358.48)).
- Root cause: the cart currently renders the **line item image**, which Shopify resolves to the **variant's** image when one is assigned, otherwise the product's featured image. This causes inconsistent thumbnails (some ghost/product-only, some model) instead of always showing the product's first image.
- Decision: **use the product's first (featured) image, then fall back to the variant/line-item image** if the product has no image.

## Necessary Info (Design/Documentation):

- **Client product structure (per client):**
  - Each **color is its own product** (colors are not variants).
  - Each product's variants are **sizes only**.
  - Color products are **stitched together via a metafield**.
  - **The first image of each product is the model image** (main image).
- No new design required — consistency fix to the existing cart thumbnail.
- Shopify reference:
  - `line_item.image` returns the variant image if assigned, else the product's featured image — https://shopify.dev/docs/api/liquid/objects/line_item#line_item-image
  - `product.featured_image` / `product.featured_media` is the product's first image — https://shopify.dev/docs/api/liquid/objects/product#product-featured_image
- Surfaces: cart page + cart drawer (same partial). **Checkout is out of scope** — see Constraints / Scope.
- **Current state:** there is currently **no fallback** if a variant image is not set — the cart relies on `line_item.image`, which already returns the product's featured image when the variant has none, but no explicit fallback is coded in the theme. This ticket adds the explicit first-image-then-variant-image logic.

## Constraints / Scope:

- **This ticket applies to the CART only** (cart page + cart drawer). It does **not** change the checkout image.
- **If carrying the image through to checkout is required, it needs a separate ticket** for a **custom checkout extension using Cart Transform** to update the line item product image. (Checkout itself is locked down in Shopify — [Fathom @41:54](https://fathom.video/calls/697645142?timestamp=2514.77).)
- **Alternative (no dev work):** the client can **update the variant image** directly if they want the model image to carry through to checkout without any development.
- Assumes **all products follow the convention** that the first image is the model image. Products that do **not** follow this convention (e.g., first image is a ghost/product-only shot) are an **edge case and out of scope** — to be handled in the future if needed. This is a content/merchandising concern (correct image ordering), not a theme bug.
