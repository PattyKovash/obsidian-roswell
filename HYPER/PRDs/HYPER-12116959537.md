## **Overview**

-  This document outlines a logic conflict between our shipping rate app (**Intuitive Shipping**) and our custom Shopify discount engine (**Roswell App / Shopify Product Discount Functions**).

-  The conflict arises when a logged-in Pro customer qualifies for a better sitewide sale discount instead of their standard Pro tier discount. While Shopify correctly applies the better sitewide discount, Intuitive Shipping incorrectly blocks the customer from receiving free shipping due to static customer account tags.

## **Current Architecture**

### **1. Shipping Rate Logic (Intuitive Shipping App)**

-  **Goal:** Provide free shipping on orders over $300 for retail customers, while forcing Pro/Wholesale tiers to pay for shipping.

-  **Mechanism:** Managed via the specific Intuitive Shipping scenario titled **"Free Shipping Over $300"**.

-  **Current Constraint:** The **"Free Shipping Over $300"** scenario uses a static condition: Customer tag does not equal outdoor-pro, wholesale, pro-member, hyper-pro. If any of these tags are present on a customer account, this specific shipping rate is completely withheld.

### **2. Pro Discount Logic (Shopify Functions)**

-  **Goal:** Dynamically apply tier discounts to specific product categories for logged-in Pro members.

-  **Mechanism:** A custom Shopify Function (Product Discount API via the Roswell App) checks customer tags at checkout and injects line-item or cart-level discounts.

-  **Shopify Native Behavior:** Shopify enforces a **"best discount wins"** architecture. If a concurrent sitewide sale (e.g., "15% OFF") offers a deeper discount than the Pro member's native tier discount, Shopify automatically drops the Pro function discount and applies the sitewide sale discount instead.

## **The Conflict (The Logic Loop)**

-  The systems are currently siloed, creating an incorrect checkout experience:

-  [Pro Customer Logs In] 

-         │

-         ▼

-  [Builds $300+ Cart during Sitewide Sale]

-         │

-         ▼

-  [Shopify Function Evaluates Discounts] ──► Sitewide Sale is better than Pro Tier. 

-         │                                  Sitewide Sale is applied.

-         ▼

-  [Intuitive Shipping Evaluates Rates]    ──► Reads static customer tag: 'outdoor-pro'.

-                                            Blocks "Free Shipping Over $300" scenario.

### **The Flaw**

-  The customer is purchasing using the **retail sitewide sale**, meaning they _should_ be treated as a retail customer and receive the **"Free Shipping Over $300"** rate. However, because Intuitive Shipping is blind to which discount actually won, it penalizes the user based solely on their account tag.

### **⚠️ Testing & Replication Constraints**

-  This bug **cannot be actively replicated or tested in production right now** due to the following environment conditions:

1.  The custom Roswell Pro discount function is currently **disabled/turned off** on the live site.

2.  Replicating this issue requires the Pro discount function to be running **at the exact same time** as an active Shopify automatic sitewide sale, allowing Shopify's "best discount wins" calculator to trigger.

-  _Dev Note: For testing, this must be staged in a development sandbox with both a mock automatic discount and the discount function enabled concurrently._

## **Proposed Technical Paths for Resolution**

-  Since Intuitive Shipping cannot natively read active discount application codes or titles, the dev team needs to implement a solution that bridges the gap between Shopify's checkout discount status and delivery rates.

### Delivery Customization Function: Hide delivery method by percent threshold/cart threshold/customer tag:

-  Delivery customization function configurations set via GraphiQL app.

-  Create a custom delivery customization function. Function logic should:

- [ ]  The delivery function only hides matched delivery methods based on cart total threshold, customer tags, percent threshold, and target delivery method strings. 

      -  **Run threshold checks if:**

- [ ]  No start and end date configured

- [ ]  If no start date AND current date & time is before the configured end date

- [ ]  Current date & time is on or after the start date AND no end date

- [ ]  Current date & time is on or after the start date AND current date & time is before end date.

- [ ]  If customer tags NOT configured

- [ ]  If customer tags configured AND user at checkout has at least 1 matching tag

      -  **Threshold logic:**

         -  If cart threshold set & cart total is >= the threshold OR no cart threshold set:

            -  If percent threshold set:

- [ ]  If any line item is discounted above the configured percent threshold, hide any delivery option that matches the configured target strings.

- [ ]  If more than 1 target string is configured, all matched delivery methods are hidden if at least 1 line item is discounted above the threshold.

            -  If percent threshold NOT set:

- [ ]  Hide any delivery option that matches the configured target strings.

- [ ]  If more than 1 target string is configured, all matched delivery methods are hidden if at least 1 line item is discounted above the threshold.

         -  If cart threshold set & cart total is < than the threshold:

- [ ]  do nothing

 

-  Function will have the below settings:

- [ ]  Percent threshold

- [ ]  Cart threshold

- [ ]  Customer tags to match

      -  Optional

      -  Array of strings

- [ ]  start date & time (make sure to process in UTC to store local time in the background)

      -  Optional

- [ ]  end date & time (make sure to process in UTC to store local time in the background)

      -  Optional

- [ ]  Ability to add target strings to match delivery option names by.

      -  This will be case sensitive
