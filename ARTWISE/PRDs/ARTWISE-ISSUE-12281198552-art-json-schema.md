## Background:

- Source requirement (fragment from the original ticket): add *"fine-art-specific fields like `artEdition`, `artMedium`, `artist` (as a `Person` entity), or `isPartOf` for print series. These are [Schema.org](http://schema.org/) `VisualArtwork` type properties."*

- Artwise sells works of fine art (originals and limited-edition prints), but the storefront currently describes every product to search engines and crawlers only as a generic Schema.org `Product`. There is no markup conveying that a product is an artwork, who the artist is, the medium, the edition size, or whether it belongs to a print series.

- Root cause: product JSON-LD is generated by Shopify's built-in `structured_data` Liquid filter in `snippets/product.liquid` (~line 914), which outputs a `Product` (no variants) or `ProductGroup` (has variants) node and **cannot be extended in place** — there is no way to inject extra properties into the filter's output.

- Decision/desired behavior: keep the existing `Product` schema untouched and **add a supplemental, linked `VisualArtwork` JSON-LD block** on the product page, populated from product metafields, so the fine-art semantics are exposed to search engines and other structured-data consumers (general SEO, AI/LLM crawlers).

## Necessary Info (Design/Documentation):

- **No new visual design required.** This is invisible markup (JSON-LD in `<head>`/template output); nothing changes on-screen.

- **`VisualArtwork` is NOT a Google rich-result type.** Google's rich-results parser does not consume the full Schema.org vocabulary, so this will **not** produce a new rich snippet on its own. The value is accurate semantic markup for SEO and non-Google consumers. Set client/stakeholder expectations accordingly. (Per Schema.org docs and Shopify community guidance — see Dev Notes references.)

- **Existing artist data:** the theme already stores artist info as text metafields and displays them in the "RS - Artist Bio" section (`sections/product-metafield-text.liquid`):
  - `product.metafields.product.Artist` — artist name (text)
  - `product.metafields.product.Artist_Bio` — bio (rich text/HTML)
  No data migration is needed — the existing `product.Artist` text value is wrapped as a `Person` node in the JSON-LD.

- **Full metafield mapping** — existing fields to include in the VisualArtwork block, plus new fields that must be created (Settings → Custom data → Products):

  **Existing metafields (already in store, no admin action needed):**

  | Schema.org property | Shopify definition name | Metafield (namespace.key) | Shopify Type | Notes |
  | --- | --- | --- | --- | --- |
  | `artist` (Person) | Artist Name | `product.ArtistFancy` | Single line text | Wrap value as `{ "@type": "Person", "name": ... }` |
  | `artMedium` | Print Type | `product.Type` | Single line text | |
  | `artform` | Style | `product.Style` | Multi-line text | |
  | `dateCreated` | Year | `product.Year` | Integer | Outputs as number e.g. `2021` |
  | `about` | Subject | `product.Subject` | Multi-line text | |
  | `color` | Color | `product.Color` | Multi-line text | |
  | `width` + `height` | Image Size | `product.Image_Size` | Single line text | Combined field (e.g. `"24 x 36"` or `"24x36"`); split on `"x"` + strip whitespace to produce two `QuantitativeValue` nodes |
  | `additionalProperty` (Condition) | Condition | `product.Condition` | Single line text | Output as `PropertyValue`; avoids schema.org's coarse 4-value `OfferItemCondition` enum |

  **New metafields to create** (not currently in the store):

  | Schema.org property | Metafield (namespace.key) | Shopify Type | Example |
  | --- | --- | --- | --- |
  | `additionalProperty` (Condition) | `product.Condition` | Single line text | `Near Mint (NM)`, `Excellent (EX)` |

- **Affected surface:** product detail page only (one file). The supplemental block renders wherever `snippets/product.liquid` is used.

- **Docs:** [Schema.org `VisualArtwork`](https://schema.org/VisualArtwork) · [Shopify `structured_data` filter](https://shopify.dev/docs/api/liquid/filters/structured_data).

## Constraints / Scope:

- **IN scope:** one supplemental `VisualArtwork` JSON-LD block on the product page, populated from product metafields, plus the metafield definitions listed above.

- **OUT of scope:** modifying or replacing the existing `{{ product | structured_data }}` output; collection/article/other-template schema; per-copy edition numbering (e.g. "12/50") — Schema.org `artEdition` is the **total** edition size only; any visible UI changes.

- **Do NOT hand-roll the full `Product` node.** Replacing the `structured_data` filter to add fields is rejected — it loses Shopify's auto-maintenance of the Product schema. The only approved approach is a **second, linked** JSON-LD block (see Dev Notes).

- **Liquid must live in the theme `.liquid` file**, not in an admin/theme-editor Custom HTML block — Liquid does not execute inside admin HTML fields, so metafield values would not resolve there.

- **Assumption:** these products are fine art and should carry `VisualArtwork`. If the catalog also contains non-art items (gift cards, framing add-ons, merch), they should not get the block — see Clarifying Questions. Until confirmed, the block self-suppresses when no art metafields are set (so non-art items are naturally excluded as long as they have no art metafields).

## Dev Notes:

- **Single source file:** `snippets/product.liquid`. The JSON-LD is emitted at ~line 914:

  {%- comment -%} current code {%- endcomment -%}
  <script type="application/ld+json">
    {{ product | structured_data }}
  </script>

- **Proposed change** — add the supplemental block immediately after the existing one. Keep `{{ product | structured_data }}` exactly as-is:

  <script type="application/ld+json">
    {{ product | structured_data }}
  </script>

  {%- liquid
    assign art_artist  = product.metafields.product.Artist
    assign art_medium  = product.metafields.product.art_medium
    assign art_form    = product.metafields.product.art_form
    assign art_surface = product.metafields.product.art_surface
    assign art_edition = product.metafields.product.art_edition
    assign art_series  = product.metafields.product.art_series
  -%}
  {%- if art_artist != blank or art_medium != blank or art_form != blank -%}
    <script type="application/ld+json">
      {
        "@context": "https://schema.org/",
        "@type": "VisualArtwork",
        "@id": {{ canonical_url | append: "#visualartwork" | json }},
        "name": {{ product.title | json }},
        "url": {{ canonical_url | json }},
        {%- if product.featured_image -%}
        "image": {{ product.featured_image | image_url: width: 1200 | prepend: "https:" | json }},
        {%- endif -%}
        {%- if product.description != blank -%}
        "description": {{ product.description | strip_html | strip_newlines | json }},
        {%- endif -%}
        {%- if art_artist != blank -%}
        "artist": { "@type": "Person", "name": {{ art_artist | json }} },
        {%- endif -%}
        {%- if art_medium != blank -%}
        "artMedium": {{ art_medium | json }},
        {%- endif -%}
        {%- if art_form != blank -%}
        "artform": {{ art_form | json }},
        {%- endif -%}
        {%- if art_surface != blank -%}
        "artworkSurface": {{ art_surface | json }},
        {%- endif -%}
        {%- if art_edition != blank -%}
        "artEdition": {{ art_edition | json }},
        {%- endif -%}
        {%- if art_series != blank -%}
        "isPartOf": { "@type": "CreativeWork", "name": {{ art_series | json }} },
        {%- endif -%}
        "mainEntityOfPage": {{ canonical_url | json }}
      }
    </script>
  {%- endif -%}

- **Why a second block (and not editing the filter):** the `structured_data` filter output is sealed. JSON-LD natively supports multiple linked nodes; reusing/linking by `@id` lets consumers associate the `VisualArtwork` data with the page's product. This keeps Shopify's auto-maintained `Product`/`ProductGroup` schema intact.

- **Existing convention to match:** artist data is already read as `product.metafields.product.Artist` / `product.metafields.product.Artist_Bio` in `sections/product-metafield-text.liquid` ("RS - Artist Bio" section). Use the same `product.*` namespace for the new metafields.

- **Always wrap values in the `json` filter** — guarantees valid JSON and prevents breakage from quotes/newlines in metafield/description data.

- **Action item (human):** create the five new product metafield definitions (`art_medium`, `art_form`, `art_surface`, `art_edition`, `art_series`) in the store admin before/with this change, and populate them on at least one test product. The dev cannot create store-level metafield definitions from theme code alone.

- **References:** [Schema.org `VisualArtwork`](https://schema.org/VisualArtwork) · [`artEdition`](https://schema.org/artEdition) · [`artMedium`](https://schema.org/artMedium) · [`artist`](https://schema.org/artist) (expects `Person`/`Organization`); `isPartOf` is inherited from `CreativeWork`. Shopify [`structured_data` filter](https://shopify.dev/docs/api/liquid/filters/structured_data) · [linking custom JSON-LD by `@id`](https://www.ilanadavis.com/blogs/articles/adding-and-linking-custom-structured-data-to-json-ld-for-seo).
