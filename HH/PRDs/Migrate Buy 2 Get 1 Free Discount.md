# Migrate Buy 2 Get 1 Free from Shopify Script to Discount Function

## Background:

The store currently uses a Shopify Script (Ruby) called **"11.26.25 - Buy 2, Get 1 Free"** to apply a 100% discount to the cheapest eligible item when a customer has 3 or more qualifying products in their cart.

**Current Script Logic**

The existing Ruby script does the following:

1. Splits cart items into a single unified eligible pool — the same products qualify for both the "buy" count and the "get" (discounted) item. There is no separate "buy product A, get product B" logic.
2. Eligibility is determined by tag-based exclusion: any product not tagged `'Free Gift'` or `'gift card'` enters the pool (case-insensitive, whitespace-stripped).
3. Calculates how many free items the customer has earned: `floor(eligible_qty / 3)`.
4. Sorts the eligible pool by unit price ascending so the cheapest item is discounted first.
5. Applies a 100% discount (line price → $0) to the earned number of items.
6. If a discount code is present that does **not** begin with `LL-`, the discount is suppressed. `LL-` codes (generated by LoyaltyLion) are allowed to coexist.


The Free Gift quantity limit (`LimitGiftCampaign`) that was bundled in the same script is **out of scope for this ticket** — it is being migrated separately. See: *Migrate Free Gift Quantity Limit*.

## Objective/Acceptance Criteria:

**Discount Function — Product Qualification**

- [ ] A Shopify Order Discount Function is created and deployed that replicates Buy 2 Get 1 Free behavior.
- [ ] The function identifies eligible products using a single unified pool for both the "buy" count and the "get" (discounted) selection.
- [ ] The function exposes the following configuration options for qualifying eligible products (via metafield or function configuration):
  - **`qualifyingCollection`** — a collection handle or ID. When set, only products belonging to this collection enter the eligible pool. Takes precedence over `qualifyingTags` if both are set.
  - **`qualifyingTags`** — one or more product tags. When set (and `qualifyingCollection` is not), only products with at least one of these tags enter the eligible pool.
  - **`excludedTags`** — one or more product tags that disqualify a product from the eligible pool regardless of other qualifiers (e.g. `["Free Gift", "gift card"]`). Tag matching is case-insensitive and whitespace-stripped.
- [ ] Products matching `excludedTags` are removed from the eligible pool even if they belong to the qualifying collection or carry a qualifying tag.
- [ ] If neither `qualifyingCollection` nor `qualifyingTags` is set, all products not matching `excludedTags` are eligible (replicates the current script behavior).

**Discount Function — Bundle Logic**

- [ ] The function exposes the following configuration options for bundle and discount behavior (via metafield or function configuration):
  - **`quantityToBuy`** — total number of eligible items required in the cart to trigger one free item (e.g. `3` — buy 2, get 1 means 3 total). Must be set to `3` to match current script.
  - **`quantityToDiscount`** — number of items to discount per completed bundle (e.g. `1`).
  - **`discountType`** — type of discount to apply. Accepts `percent` or `fixed_amount`.
  - **`discountAmount`** — the discount value. For `percent`, `100` = free. For `fixed_amount`, value in currency units.
  - **`discountMessage`** — the label shown on the discounted line item at checkout (e.g. `"BUY 2, GET 1 FREE"`). 
  - **`enableDevTest`** — a dev mode flag. When enabled, the function triggers discount logic against a designated test product/condition. Reference implementation: [`enableDevTest` in delivery-po-box-validation](https://github.com/roswell-studios/BAUBLEBAR_CE_EXT/blob/release/_candidate/extensions/delivery-po-box-validation).
- [ ] With 3+ eligible items in cart, the cheapest eligible item is discounted per `discountAmount` and `discountType`.
- [ ] With 6+ eligible items, 2 items are discounted (every multiple of `quantityToBuy` earns one additional free item).
- [ ] With fewer than 3 eligible items, no discount is applied and the cart is unaffected.
- [ ] The cheapest eligible item (by unit price, ascending) always receives the discount first.

**Discount Function — Discount Code Handling**

- [ ] If the B2G1 discount gets applied applies, when a discount code beginning with `LL-` is present, the discount code is not removed.
- [ ] If the B2G1 discount gets applied applies, when a discount code does NOT beginning with `LL-` is present, remove the discount code.
- [ ] When no discount code is present, the B2G1 discount applies normally if eligibility is met.

**Dev Mode**

- [ ] `enableDevTest` is disabled by default and must not affect production behavior when off.
- [ ] When enabled, the function applies discount logic against a designated test product/condition without requiring real eligible products in the cart.
- [ ] Dev mode can be toggled without a code deploy (via metafield or function configuration).

**General**

- [ ] The existing Shopify Script is unpublished/removed after the function is confirmed working.
- [ ] Function is tested on a staging/dev environment before going live, using `enableDevTest` to verify discount and code rejection behavior.
- [ ] Edge cases covered: all items excluded (no eligible pool → no discount), exactly 3 items (1 free), mixed eligible/excluded items in cart.
- [ ] Free Gift quantity limiting behavior is **not** handled in this function (separate ticket).

**General Constraints**
- Shopify functions will not stack or combine with other automatic discounts or discount codes when they target the same line item. Native Shopify behavior is the best discount is applied.

**Not in Scope**

- Function UIs. Functions will be configured with GraphiQL app.
- Free Gift quantity limit (separate ticket: *Migrate Free Gift Quantity Limit*).

## Dev Notes:

- The script applied the discount to the line item's total line price, not the unit price — ensure the function targets line-level pricing correctly when quantities > 1 are split.
- `enableDevTest` pattern: see [delivery-po-box-validation](https://github.com/roswell-studios/BAUBLEBAR_CE_EXT/blob/release/_candidate/extensions/delivery-po-box-validation) for the reference implementation used on BAUBLEBAR.
