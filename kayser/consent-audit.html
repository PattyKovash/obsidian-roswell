Hue — Existing Cookie Banner

  • Critical
    Dark-pattern CSS hides the decline button. In config/settings_data.json:311, under platform_customizations > custom_css:
    #shopify-pc__banner__btn-decline,
    #shopify-pc__prefs__header-decline { display: none; }

    This hides both the main "Decline" button and the preferences-modal "Decline" button on Shopify's native privacy banner. Visitors see only "Accept" with no equally prominent way to refuse. This is a textbook GDPR/ePrivacy violation.

    Location: Added via Shopify admin (Theme Settings > Custom CSS), not in liquid files. Must be removed in admin.

How the banner works today

The banner is rendered by DataGrail, which loads through GTM (not hardcoded in the theme). The snippet c-gtm-datagrail.liquid provides the bridge between DataGrail's DG_BANNER_API and Shopify's Customer Privacy API. If the GTM container is the old, inaccessible one, DataGrail's banner may still be loading through it—removing or swapping the GTM container will also kill the DataGrail banner, which is the intended outcome since it's being replaced with Shopify's native banner.

NoNonsense — Banner & Consent

Confirmed: No cookie banner exists on this store. No consent popup, GDPR bar, or third-party consent library (OneTrust, Cookiebot, etc.) found in theme code.

Dead consent bridge code

The c-gtm-datagrail.liquid snippet contains DataGrail bridge code identical to Hue—it references DG_BANNER_API, registers callbacks on window.dgEvent, and calls setTrackingConsent. But DataGrail is not loaded from theme code; it would need to load through GTM. If DataGrail is not installed or the GTM container is dead, this code never fires, meaning Shopify's consent state is never explicitly set by the theme. In regions where the native banner is not configured, all processing defaults to allowed.

Same preferences: true issue

The bridge code at c-gtm-datagrail.liquid:53-61 hardcodes preferences: true and maps sale_of_data to categoryEnabled("marketing")—same flaw as Hue. The sale_of_data mapping may not be correct for CCPA/CPRA opt-out requirements.

dataLayer

Only the standard GTM init push ({'gtm.start': ...}) exists. No gtag('consent', ...) calls, no custom dataLayer pushes for e-commerce events.

What this means for Phase 1 scope

The work is not just "enable the native banner." Phase 1 must include:

  • Hue: Remove dark-pattern CSS (admin). Remove or consent-gate Postscript (theme.liquid:4). Remove hardcoded Klaviyo snippet. Clean up or remove the DataGrail bridge code. Verify/swap GTM metafield.
  • NoNonsense: Remove or consent-gate ShopMy (theme.liquid:363). Evaluate Dash Hudson. Remove hardcoded Klaviyo snippet. Clean up or remove the DataGrail bridge code. Verify/swap GTM metafield.
  • Both: Enable native Shopify banner for agreed regions. Audit all custom pixel permission settings in admin. Verify app embed consent behavior.

Required Human Checks (Shopify Admin)

These cannot be determined from theme code. Someone with admin access must check both stores.

Both stores

  • Settings > Customer events: List all app pixels and custom pixels. For each custom pixel, check the Permission setting (Required vs. Not required).
  • Settings > Customer privacy: Current banner status, configured regions, data sharing opt-out page, privacy policy link.
  • Shop metafield custom.cart_gtm_id: Is it populated? What container ID is stored? Is it the old (inaccessible) or new container?
  • Installed apps: Is DataGrail installed/active? Is the Google & YouTube channel app installed? Meta? Others?
  • Sales channel apps: Which are installed—Google & YouTube, Meta, TikTok, Pinterest?
  • Privacy policy: Must be published and linked before the native banner can be enabled.

Hue only

  • Platform custom CSS: Confirm the dark-pattern CSS (#shopify-pc__banner__btn-decline { display: none }) and remove it via Theme Customize > Theme Settings.
  • Live site: Visit the live site from an EU IP / VPN. Does the DataGrail banner currently appear? Is the decline button hidden?

NoNonsense only

  • Microsoft Clarity pixel permissions: Given session recording sensitivity, confirm its permission is set to "Required" (analytics + marketing purposes).

MP Draft — Issues & Corrections

Original draft

Scope: This 6-hour estimate is strictly for the native shopify consent setup. It excludes GTM/analytics integration, so no data will be sent to tracking tools yet.

Recommendation: While we ideally advise routing all tracking through GTM, as an immediate first step toward full compliance, we recommend implementing a consent banner now.

Next Steps: Please let us know if you'd like to proceed with the direct setup now, start with an audit of existing Shopify scripts/tracking, or hold off and do everything in one go.

What's wrong

  • Issue
    "No data will be sent to tracking tools yet" is false. Data is already being sent, right now, without consent. Postscript, Klaviyo, and ShopMy fire on every page load. The banner doesn't stop these—they're hardcoded in the theme and bypass Shopify's consent framework entirely. This sentence gives the client false comfort.
  • Issue
    "6 hours strictly for the native Shopify consent setup" misframes the work. Enabling the native banner is an admin toggle. The actual hours go into the cleanup: removing dark-pattern CSS, pulling out hardcoded scripts, verifying app pixel permissions, and testing. The estimate isn't wrong per se, but the description of what the time covers is.
  • Issue
    "Start with an audit" presented as an alternative to proceeding. The audit is a prerequisite, not an option. You can't safely enable a consent banner without knowing what bypasses it—and now the audit has found scripts that do exactly that.
  • Issue
    "Hold off and do everything in one go" understates compliance exposure. Brand A has a dark-pattern banner today. Brand B has no banner at all. Both have scripts firing without consent. Waiting increases risk.
  • Issue
    Fidel framing implies nothing can start. Phase 1 has zero GTM dependency. Fidel's work (GTM rebuild + consent bridge) is Phase 2. The draft conflates the two phases.
