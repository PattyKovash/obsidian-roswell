Consent Compliance Roadmap

Phase 1 order of operations, estimates, and execution model (human vs. AI agent)

2026-09-21 · Based on theme audit findings · Both stores

Estimate Overview

3–4h
Human only
1–2h
AI agent (guided)
5–7h
Total Phase 1

"AI agent (guided)" means Claude executes the code changes with a human reviewing and approving. The human still needs to be present—this isn't unattended. The time estimate reflects elapsed time including review.

Why this isn't 6 hours of "banner setup": The banner toggle itself is ~15 minutes per store. The hours go into the cleanup the audit surfaced—hardcoded scripts that bypass consent, dark-pattern CSS, dead DataGrail bridge code, GTM metafield verification, and QA. Framing it as "banner setup" undersells the scope and misleads the client about what they're paying for.

Order of Operations

Prerequisite — Before touching anything
01 Admin reconnaissance
Human only ~45 min (both stores)

A human with Shopify admin access documents the current state. This informs every subsequent step.

  • Settings > Customer events: Screenshot or list every app pixel and custom pixel. For each custom pixel, note the Permission setting (Required vs. Not required).
  • Settings > Customer privacy: Current banner status, configured regions (if any), data sharing opt-out page, privacy policy link.
  • Shop metafield custom.cart_gtm_id: What container ID is stored? Check via Settings > Custom data, or inspect the live page source for gtm.js?id=GTM-XXXXXXX.
  • Installed apps: Is DataGrail installed? Google & YouTube channel? Meta? List all apps that could have tracking implications.
  • Privacy policy: Is it published and linked? The native banner requires it.
Blocks: everything. This step produces the information needed for steps 2–7.
02 Client decisions
Human only Async (not billable, but blocks step 6)

Legal and regional decisions that belong to the client, not the agency:

  • Which regions get the banner? (UK/EEA is automated if those are active markets; US, Canada, and other regions are opt-in.)
  • Is a US data-sharing opt-out page needed? (Depends on whether they sell data under CCPA/CPRA definitions.)
  • Confirm the privacy policy is current and covers all the tracking the audit found (Postscript, Klaviyo, ShopMy, Dash Hudson, etc.).
Blocks: step 6 (banner configuration). Steps 3–5 can proceed in parallel.
Theme cleanup — Can run in parallel with client decisions
03 Remove dark-pattern CSS Urgent
Human only ~15 min (Hue only)

In Shopify admin for Hue: Online Store > Themes > Customize > Theme Settings, find the platform custom CSS field and delete:

#shopify-pc__banner__btn-decline,
#shopify-pc__prefs__header-decline { display: none; }

This is the most urgent fix—it's an active GDPR violation. It must be done in admin because it's in platform_customizations, not a liquid file.

NoNonsense does not have this CSS. Hue only.

No dependencies. Do this first, today if possible.
04 Remove/gate hardcoded tracking scripts
AI agent + review ~45 min (both stores)

An AI agent can execute these code changes with human review before pushing:

Hue

  • Remove Postscript SDK from layout/theme.liquid:4. The client should re-add it as a Shopify custom pixel with Permission set to "Required" (marketing), so the consent framework governs it.
  • Remove hardcoded Klaviyo snippet—delete the {% render 'c-klaviyo' %} call from layout/theme.liquid:328. Klaviyo already has an app embed enabled; the hardcoded snippet causes double-loading and bypasses consent.

NoNonsense

  • Remove ShopMy affiliate script from layout/theme.liquid:363. Re-add as a custom pixel with "Required" permission if the client still uses it.
  • Evaluate Dash Hudson (blocks/c-block-dashhudson.liquid). If it's a social gallery embed (functional content), it may not need consent gating. If it includes tracking/analytics beyond the gallery, it should be gated. Flag for human decision.
  • Remove hardcoded Klaviyo snippet—same as Hue. Delete the {% render 'c-klaviyo' %} call from layout/theme.liquid:344.

After removing these, the Klaviyo app embed handles Klaviyo on both stores. Postscript and ShopMy move to custom pixels (human creates those in admin). Verify the Attentive footer form proxy (attentive-proxy.rs-workers.workers.dev) is documented in the privacy policy.

Depends on: step 1 (to confirm app embeds are active before removing hardcoded duplicates).
05 Clean up GTM & DataGrail bridge code
AI agent + review ~30 min (both stores)

The c-gtm-datagrail.liquid snippet on both stores contains:

  • GTM loader (container ID from metafield)
  • DataGrail consent bridge (DG_BANNER_API callbacks → setTrackingConsent)

Two possible paths depending on step 1 findings:

  • If the old GTM container is in the metafield: Clear the metafield value (human, in admin) or swap it to the new container ID. If swapping, leave the GTM loader code intact for Phase 2. If clearing, the loader becomes inert (gated by != blank).
  • DataGrail bridge code: Remove the entire DataGrail section (lines ~25–74 in both files) regardless. It references an API that's being decommissioned, hardcodes preferences: true, and will be replaced by Shopify's native consent + a new GTM bridge in Phase 2.

An AI agent can strip the DataGrail bridge code. The metafield change is human (admin).

Depends on: step 1 (to know the metafield value and whether DataGrail is installed).
Banner activation — After cleanup and client decisions
06 Configure native Shopify banner
Human only ~30 min (both stores)

In Shopify admin for each store: Settings > Customer privacy.

  • Enable the cookie banner for the regions the client agreed to in step 2.
  • Link the privacy policy (required before the banner activates).
  • If the client wants a US data-sharing opt-out: create the opt-out page and link it.
  • Review the banner text/appearance options if any customization is desired.

This is an admin-only operation. The banner is not theme code—it's a Shopify platform feature. "Enable" is the right word, but it's not a single toggle: you're configuring regions, linking policies, and making choices about data-sharing opt-out. Allocate time for reading the options and making deliberate choices.

Depends on: step 2 (client decisions on regions), step 3 (dark-pattern CSS removed).
07 Audit and fix custom pixel permissions
Human only ~30 min (both stores)

In Settings > Customer events, review every custom pixel:

  • Any custom pixel set to "Not required" fires regardless of consent. Change to "Required" and select the appropriate purposes (analytics, marketing, etc.) unless there's a specific reason it must always fire.
  • Pay special attention to Microsoft Clarity on NoNonsense—session recording has elevated privacy sensitivity and should definitely require analytics consent.
  • App pixels (vs. custom pixels) declare their own permissions—you can't change those, but you can verify they're reasonable.
Depends on: step 1 (to have the list of pixels).
Verification
08 QA consent behavior
Human + AI guidance 1.5–2h (both stores)

Test from inside and outside configured regions. An AI agent can provide the QA checklist and help interpret network logs, but a human must operate the browser.

From a configured region (EU VPN)

  • Banner appears on first visit
  • Decline button is visible and equally prominent as Accept
  • Before consent: no marketing/analytics cookies set, no tracking network requests (check DevTools > Network for klaviyo, postscript, shopmy, clarity, triplewhale, impact domains)
  • After accepting: appropriate scripts fire
  • After declining: scripts do not fire
  • Preferences can be changed after initial choice
  • Consent persists across page navigation

From a non-configured region (US, unless configured)

  • No banner appears (expected default)
  • All processing allowed by default (expected behavior)

Edge cases

  • Test the community-reported issue: does the sandboxed visitor_consent_collected pixel event fire for Shopify's native banner? If not, custom pixels that rely on it won't get consent signals.
  • Verify the Klaviyo app embed properly respects consent (it should, through Shopify's pixel framework, but confirm).
  • Check that removing the hardcoded Klaviyo snippet doesn't break any functionality that the app embed doesn't cover (e.g., specific event tracking the snippet had).
Depends on: steps 3–7 all complete.

What Phase 1 Does Not Cover

These belong to Phase 2 (Fidel, GTM rebuild). Listing them here so the scope boundary is clear:

  • Building the GTM consent bridge (gtag('consent', 'default', ...) and gtag('consent', 'update', ...))
  • Deciding where GTM loads (theme.liquid, custom pixel, or both)
  • Building tags, triggers, and variables in the new GTM containers
  • Google Consent Mode v2 implementation
  • Checkout tracking (GTM in checkout requires a custom pixel with sandbox limitations)
  • End-to-end QA of the full analytics pipeline

Parallelism & Dependencies

Steps 3, 4, 5, and 7 can run in parallel after step 1. Step 6 waits on client decisions. Step 8 (QA) waits on everything.

Critical Path for the MP

What the client needs to hear:

The audit found tracking scripts on both stores that fire without consent—including scripts that send customer emails and set cookies on every page load. On Hue, the existing cookie banner has CSS that hides the "Decline" button. On NoNonsense, there is no consent mechanism at all.

Phase 1 fixes this. It's 5–7 hours across both stores: removing the non-compliant code, enabling Shopify's native consent banner for the agreed regions, and verifying everything works. It does not require GTM or Fidel—that's Phase 2.

We need three things from the client before we can configure the banner: (1) which regions, (2) whether a US data-sharing opt-out page is needed, and (3) confirmation the privacy policy is current. The cleanup work can start immediately while those decisions are pending.
